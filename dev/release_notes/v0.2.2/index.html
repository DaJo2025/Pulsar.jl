v0.2.2 release notes

Released: 2026-10.

v0.2.2 adds batched GPU execution, an ensemble-averaging layer and a single implementation of the fidelity metrics shared by every kernel, and fixes a set of gradient and physics bugs. Several fixes and two convention changes alter optimized results — read Changes in behavior before upgrading.

New

  • Batched GPU backend. CUDA (batched eigensolves and strided GEMMs) and Metal (opt-in FP32 kernel) as package extensions, with zero-config setup: detect_gpu_hardware, setup_gpu!, load_gpu!. The CPU remains the default and the fallback is exact.
  • Spherical-tensor anisotropy engine shared by MAS, EPR and DNP. DNP systems now include g-anisotropy, hyperfine, dipolar and CSA terms.
  • Fidelity metrics on the Φ^X_Y grid — :prop_real, :prop_modulus, :prop_squared, :state_real, …, :dm_squared, plus :state_squared_haar (average gate fidelity) — selectable with metric = on targets and kernels, all computed by one shared implementation (overlap_fidelity, overlap_weight). The SU(2) kernel accepts the full propagator and state rows; the Lindblad kernels add :dm_modulus. See Fidelity metrics.
  • Ensemble averaging. EnsembleAveraging and ensemble_averaging average the fidelity and its gradient over offsets, couplings, B1 / Rabi scale, drive phase, timing, any added Hamiltonian term or any custom change, and over input states, with mean, signed sum, worst-case, CVaR or softmin aggregation. Use it through grape_optimize(…; ensemble), ensemble_objective, MRControl(…; ensemble), LindbladMRControl(…; ensemble), SU2Kernel(ens, …) and SpinIKernel(ens, …). offset_operator and coupling_operator give the right operator for every spin system and QC platform. See Ensemble averaging.
  • grape_gate_kernel — a propagator-level gate objective for the MR layer.
  • Optimizer callbacks receive the current controls as w =.

Fixes that change results

  • MAS / EPR powder gradient was wrong (the target was dropped from the gate gradient; the state gradient used the wrong part of the overlap).
  • MAS omitted the magic-angle rotor projection and the CSA asymmetry, so anisotropy did not average out under spinning. MAS sideband numerics change.
  • DNP powder averaging was a no-op.
  • band_selective_fidelity / band_selective_gradient added the offset as a global phase, so every band scored the same. The offset now detunes the spins (Σ Iz); a bare QuantumSystem has no z operator and now raises an error.
  • Gradients: :modulus metrics (missing phase factor); spin-I and Trotter state transfer; SU(2) :state_squared; grape_tracking_kernel was twice the true value, which mattered whenever tracking was combined with penalties.
  • The MR state kernel gradient is exact. grape_state_kernel (behind MRControl / optimcon) used a first-order step derivative, a few percent off at typical step sizes and more for coupled spins, which could stall an optimizer short of the optimum. Every path — generic, spin-½ fast path, single-member and batched / GPU — now returns the exact derivative of the reported fidelity. Fidelities are unchanged; optimizer trajectories change.
  • Bounded grape_cg_optimize / grape_lbfgsb_optimize could report a fidelity higher than the returned controls achieve.
  • lbfgsb_optimize, lbfgs_optimize, bfgs_optimize no longer learn curvature from a failed line search. Near an optimum with an approximate gradient this could blow up the step (and overflow a propagator) and wasted every remaining iteration.
  • Crashes: transmon_system (every call), SpinIKernel(…; amp_factors), MAS / EPR / DNP / Bloch optimcon with fidelity hooks, MRI optimcon, LindbladMRControl with a callback, and EPR band-selective objectives.
  • Pulser export produced a script Pulser cannot run. It now writes CustomWaveform amplitudes in rad/µs and Pulse.ArbitraryPhase, in Pulser's own Hamiltonian convention.

Changes in behavior

  • Spin-I RF phase follows the NMR / SU(2) convention, field Ω(Ix cos φ + Iy sin φ). Spin-I pulses optimized with earlier versions reproduce with φ → −φ.
  • Neutral atoms use |g⟩ = |0⟩, |r⟩ = |1⟩ throughout: the detuning is Δω·|r⟩⟨r| (was Δω/2·σz) and T1 decays |r⟩ → |g⟩ (was the reverse). Runs with a nonzero detuning or a finite T1 change.
  • Metric names. The old names (:real, :square, :normalized, :average, RealGate, …) still work with a one-time deprecation warning. :prop_average is now :state_squared_haar.
  • DM-Real is the raw Re Tr(ρ_t† ρ), no longer clamped to [0, 1]; operator transfer can legitimately score below zero.
  • MRControl / LindbladMRControl accept ensemble =; rho_init and rho_targ may then be omitted when the ensemble supplies the state pairs.
